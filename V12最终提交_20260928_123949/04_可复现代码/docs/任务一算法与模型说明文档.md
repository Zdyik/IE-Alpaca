# 任务一事故风险预测：算法与模型说明文档

**模型版本：V12 State-MAE**  
**文档日期：2026-09-28**  
**任务目标：根据每辆车连续60天的驾驶记录，输出随后40天发生事故或未遂事故的概率。**

## 1. 方案摘要

本项目把任务定义为车辆级事故风险排序问题。事故口径为事件`11803`或`11804`至少出现一次，最终输出每辆车的风险概率和按固定阈值0.5得到的二分类结果，主要评价指标为ROC-AUC。

当前保留模型为**V12 State-MAE**。模型先通过遮住部分驾驶记录再恢复它们，学习六类驾驶状态；随后使用可观察到的事故结果训练每日首次事故风险率。SSL没有把事故事件作为未来预测目标，也不读取验证车、锁定车或第61—100天结果；但训练车辆60天观测期内已经发生的`11803/11804`属于历史记录，可以参加同日遮蔽恢复。六类状态分别表示驾驶暴露、上游危险行为、控制稳定性、近端险情、严重历史和数据质量。人工知识只用于给事件分组提供初始化和很弱的语义约束，每类事件的实际作用和归属比例仍由模型学习。

本文报告的性能来自382辆开发车的车辆级OOF预测，不是96辆锁定测试车的独立测试成绩。锁定测试车尚未评分。

完整流程如下：

```mermaid
flowchart LR
    A[原始事件、GPS轨迹、IMU] --> B[每车每天特征]
    B --> C[24类事件节点和31项上下文]
    C --> D[六类驾驶状态]
    D --> E[4层因果TCN编码历史变化]
    E --> F[State-MAE遮蔽恢复预训练]
    F --> G[右删失风险微调]
    G --> H[每日风险率 q]
    H --> I[40天概率 p40]
```

模型规模有意控制在小模型范围。为兼容全部消融，预训练对象登记了93,502个`requires_grad`参数，完整下游对象登记119,542个总参数；在最终State-MAE模式中，真正获得自监督梯度的学生参数约41,892个，风险概率有效前向路径约47,871个。数据只有数百辆可监督车辆，使用数千万参数的网络会显著增加过拟合和实验波动，并不会自然带来更高的泛化能力。

## 2. 任务定义与数据边界

### 2.1 最终预测目标

对第60天日末的车辆历史`X₁:₆₀`，希望估计：

```text
P(第61—100天至少出现一次11803或11804 | X₁:₆₀)
```

模型首先输出每日首次事故风险率`q`，再换算为未来`H`天至少发生一次事故的概率：

```text
pH = 1 - (1 - q)^H
```

最终交付使用`H=40`。`q`不是人工计算的风险分数，而是通过事故监督损失学习得到的概率。这里假设：给定一个预测锚点的历史后，随后窗口内每日条件风险率近似保持为同一个`q`。该假设让不同删失长度可以共同训练，但也限制了40天概率的校准能力；本地数据不能检验第61—100天的风险率是否真的恒定。

### 2.2 本地标签的限制

本地数据只覆盖60天，没有第61—100天的真实事故结果，因此无法直接验证最终60→40预测。训练时在同一60天观测期内设置较早的预测锚点：

| 锚点 | 可用历史 | 可观察未来 |
|---:|---:|---:|
| 14 | 14天 | 40天 |
| 20 | 20天 | 40天 |
| 30 | 30天 | 30天 |
| 40 | 40天 | 20天 |
| 50 | 50天 | 10天 |
| 53 | 53天 | 7天 |

较晚锚点没有观察到的未来天数按右删失处理，不会被填成“没有事故”。最终模型把这些较早锚点学到的关系迁移到完整60天历史，这是现有数据下不可避免的外推假设。

标签从锚点次日开始计算。例如锚点20的第1个结果日是第21天。“首次事故”指锚点之后首次出现`11803/11804`，并非车辆生命周期中的首次事故；锚点之前发生过事故的车辆仍可继续进入后续风险集。同一天出现多次事故或同时出现事故与未遂事故时，都合并为该日发生一次结果事件。开发车各窗口正例数分别为：14→40有103辆、20→40有119辆、30→30有112辆、40→20有105辆、50→10有62辆、53→7有45辆。

### 2.3 车辆级划分

500辆目标车中，478辆具有可靠匹配的事件监督，22辆没有可靠事件源。冻结划分如下：

- 382辆进入开发训练池；
- 96辆作为锁定测试池；
- 开发池内部采用5折车辆级交叉验证；
- 随机种子固定为2026；
- 同一辆车的全部日期、全部锚点和全部自监督窗口只能出现在同一侧。

首次划分按20→40标签进行分层抽样，20%进入锁定池；开发池再按同一标签进行5折分层。五个验证折的20→40正负例数依次为`24/53、24/53、23/53、24/52、24/52`。22辆没有可靠监督的车辆在划分前排除，最终推理时再补回。冻结名单位于数据库目录的`任务一实验结果/splits/split_v1_seed2026.json`，文件同时保存标签指纹，标签变化时程序会拒绝复用旧划分。

每个外折的标准化参数、自监督预训练、轮数选择和模型训练都只使用该折训练车辆。外折验证车辆的无标签记录也不进入自监督预训练。96辆锁定车辆尚未用于拟合、选模或指标计算；它们的分组标签仅在最初生成分层名单时使用，此后保持封存。

## 3. 数据预处理与特征工程

### 3.1 日级数据表

原始事件、GPS轨迹和IMU数据只进行一次清洗，并汇总为`500辆车 × 60个日历日`的完整日表。每行表示一辆车在一天内的驾驶状态。主要处理包括：

1. 统一车辆编号和时间格式，去除无法确定车辆或日期的记录；
2. 过滤观测期以外的数据；
3. 将连续报警合并为报警段，同时保留原始触发次数；
4. 从GPS计算里程、驾驶时长、夜间里程、行程次数和速度变化；
5. 将IMU先按短时间窗汇总，再计算每天的加速度、变化幅度和角速度特征；
6. 为轨迹缺失、IMU缺失、静止日和异常记录生成单独标记；
7. 为没有记录的日历日补行，但保留“真实零值”和“没有观测”的区别。

关键清洗规则固定为：同类事件相邻触发间隔超过60秒才开始新的报警段；夜间定义为22:00—06:00；轨迹长间隔定义为相邻记录超过60秒；速度高于3 km/h视为移动，轨迹回退积分只接受1—30秒间隔；IMU按10秒窗汇总，使用加速度模长和角速度模长等旋转不变特征。完整阈值记录在预处理运行的元数据中。

预处理输出保存在数据库目录的`任务一预处理结果/daily_features.parquet`。V12直接读取这张日表，不在每次实验时重复扫描原始大文件。

### 3.2 24类行为事件

V12保留全部24类事件，不先把它们加成一个手工风险分数。人工分组只表达事件在驾驶过程中的大致角色：

| 状态 | 事件代码及含义 |
|---|---|
| 暴露与机会 O | `60292`后盲区报警、`60294`右盲区报警 |
| 上游危险行为 U | `11401`路口超速、`11402`主路弯道超速、`11403`危险路段超速、`11405`匝道超速、`11406`高速长下坡超速、`41001`疲劳闭眼、`41003`注意力分散、`41023`看手机、`41029`困倦 |
| 控制稳定性 C | `30002`左车道偏移、`30003`右车道偏移、`30017`长时间压线、`41002`打哈欠、`41004`打电话、`41005`抽烟、`41009`频繁低头 |
| 近端险情 P | `30000`前碰撞预警、`30005`车距过近 |
| 严重历史 H | `11803`事故、`11804`未遂事故 |
| 证据质量 Q | `41006`摄像头遮挡、`41021`摄像头角度扭转 |

每类事件每天形成8项输入：

| 输入 | 直白含义 |
|---|---|
| `log_count` | 当天原始触发次数，经`log1p`压缩 |
| `log_episodes` | 当天独立报警段数，经`log1p`压缩 |
| `log_rate_100km` | `log1p(100×次数/(里程+100))` |
| `log_rate_hour` | `log1p(次数/(驾驶小时+1))` |
| `occurred` | 当天是否出现过该事件 |
| `km_observed` | 当天里程是否可靠可见 |
| `hours_observed` | 当天驾驶时长是否可靠可见 |
| `night_share` | 当天夜间里程占比 |

同时使用次数、报警段和单位暴露率，可以避免模型只把“开得多”误判成“更危险”。`log1p`减少极端大值的影响，是否发生标记则保留稀疏事件的清晰边界。

### 3.3 31项上下文

除事件节点外，每天还输入31项上下文：

- **14项连续特征：** 里程、驾驶时长、夜间里程、行程开始次数、速度中位数、速度90分位数、速度变化90分位数、转向变化90分位数、有效IMU窗口数、加速度峰值99分位数、加速度波动90分位数、角速度峰值、无效里程记录数、长时间间隔记录数；
- **3项质量标记：** 当天是否有轨迹、是否有IMU、是否为已观察静止日；
- **14项缺失标记：** 对每项连续特征单独说明其原值是否缺失。

设备号、绝对经纬度、结果窗口数据和截止时间不明确的画像统计不进入模型。

GPS侧优先使用设备累计距离与运行时间计算有效增量，在无法使用时才以速度乘时间间隔回退；IMU先在10秒窗中计算模长峰值、分位数和波动，再聚合到日级。这里列出的是V12实际选用的特征，预处理日表还保存了若干审计列，但它们不进入该模型。

### 3.4 折内数值处理

所有数值处理只在当前训练车辆的第1—53天拟合：

- 事件强度按训练数据99分位数截断并缩放；
- 连续上下文先做带符号的`log1p`；
- 按训练数据1%和99%分位数截尾；
- 缺失值使用训练车辆中位数填充；
- 再按`(x-训练中位数)/训练标准差`进行缩放；
- 缺失标记与填充值同时输入模型。

变换参数只用训练车辆第1—53天估计，随后原样应用于训练车辆第54—60天、验证车和最终第60天推理。自监督预训练本身读取外折训练车辆的完整60天序列；第1—53天限制只用于防止较晚日期影响数据变换参数。验证车或锁定车不能改变任何截尾点、中位数或缩放系数。

## 4. 最终模型架构

### 4.1 从事件到六个驾驶状态

每个事件的8项输入经过`8→32→32`的共享MLP，激活函数为GELU；再拼接8维事件编号、4维行为角色和4维风险阶段向量，并通过`48→32`线性层得到事件表示。模型学习一个`24 × 6`的软归属矩阵：

```text
事件归属 = softmax(可学习参数 + 人工分组初始化)
```

因此一个事件可以同时对多个状态产生影响。例如“频繁低头”最初属于控制状态，训练后仍可向上游危险行为分配一部分权重。另一个动态门控网络根据当天事件内容和暴露状态调整事件强度，解决“同一种事件在不同驾驶量下含义不同”的问题。

归属softmax沿六个状态计算。初始时事件主状态logit为2，其余状态为-1；训练中的弱交叉熵只防止状态语义完全漂移。事件门控为`64→32→1`的Sigmoid网络。31项上下文分别经过`31→32→32`网络，作为暴露、控制和质量节点加入O、C、Q状态。最终每天得到6个32维状态向量。

### 4.2 时间编码

六个状态共用4层因果TCN，卷积核为3，膨胀系数为`1/2/4/8`，理论感受野为31天。每层使用左侧填充、深度可分离卷积、GELU、Dropout、残差连接和LayerNorm。因果结构保证第`t`天的表示只读取第1—`t`天，不会看到预测锚点之后的数据。

共享TCN有两个目的：一是减少参数量，二是让不同状态共享一般的时间变化参数。状态编号向量负责区分六种状态的含义。TCN对六个状态分别沿时间处理，本身没有直接的同日跨状态消息；跨状态联系来自事件软归属和联合解码器。最终未采用的HRC实验才显式加入状态间有向消息。

### 4.3 State-MAE自监督预训练

预训练时主动遮住一部分已知记录，让模型根据该状态未遮蔽的过去历史、事件软归属带来的关联信息和联合解码约束恢复它们：

1. 随机遮住完整事件包，而不是只遮一个派生值；
2. 连续2—5天遮住一个完整状态，例如同时遮住所有疲劳、分心和超速事件；
3. 使用无梯度EMA教师产生稳定的隐藏状态目标；
4. 原本缺失的位置不计算重建误差，防止把缺失误当成零值；
5. 严重历史状态降低遮蔽概率，防止大量事故零值主导训练。

每个批次为每辆车抽取两个状态块，每块连续2—5天；状态抽样概率为`O/U/C/P/H/Q = 0.15/0.23/0.22/0.18/0.05/0.17`。此外随机选择约10%的日期遮住全部事件，并选择约8%的事件类型在整段序列中遮蔽；约8%的上下文通道会被连续遮住2—5天。被遮事件加上独立mask token，解码器用六状态联合表示恢复`24×8`事件输入和31项上下文。历史中已经观察到的`11803/11804`可以参加当前状态遮蔽恢复，但它们明确不进入1/3/7日的未来SSL目标。

最终保留模型的预训练损失为：

```text
Lmask = 事件是否发生损失
      + 0.50 × 正值事件强度损失
      + 0.50 × 上下文恢复损失
      + 0.25 × EMA隐藏状态恢复损失
      + 0.01 × 事件归属弱约束
```

V12实验还测试了1/3/7日状态变化预测和有向风险链，但它们没有达到预先规定的增益门槛，因此最终State-MAE不使用这些模块。

### 4.4 风险头

对每个预测锚点，风险头读取：

- 六个状态的全部历史平均值，表示长期驾驶倾向；
- 六个状态最近14天平均值，表示近期状态；
- U、C、P最近7天与此前7天的差值，表示风险趋势。

这些表示拼接后进入`64维隐藏层 → 1个风险logit`的小网络，经过Sigmoid得到每日首次事故风险率`q`。最终State-MAE中的未来动态与图边输入固定为零，只用于保持消融实验的网络接口和参数口径一致，不参与有效预测。

正式实验报告的93,502个自监督`requires_grad`参数和119,542个下游总参数包含了为统一接口而保留、但在State-MAE模式中没有梯度的动态预测器，以及风险头中乘以固定零输入的权重。最终State-MAE真正参与自监督梯度的学生参数约41,892个；风险概率有效前向路径约47,871个参数。登记总参数用于核对实验对象，后两个数字更能反映最终模型的实际容量。

## 5. 监督目标与损失函数

### 5.1 右删失事故损失

对每个锚点，风险头产生一个在后续可观察窗口内近似恒定的每日风险率`q_t`。设最多可观察`c=min(40,60-t)`天。如果锚点之后首次事故发生在第`j`天，损失为：

```text
L = -(j-1)log(1-q) - log(q)
```

如果观察到第`c`天仍未发生事故，损失为：

```text
L = -c log(1-q)
```

未观察的未来不进入损失。每辆车的六个锚点先平均，再跨车辆平均，避免把同一辆车的多个时间点当成六辆独立车辆。

### 5.2 辅助监督

微调阶段同时预测未来7天是否出现控制异常、近端险情和严重事件，权重为0.10。辅助任务帮助状态编码器保留风险阶段信息，但最终概率仍由右删失事故损失决定。

完整微调目标为：

```text
Lfinetune = L右删失事故 + 0.10 × L未来7天阶段
```

| 稳定训练 | 梯度裁剪 | 1.0 |
| 最终重训 | 固定轮数 | 18 |

训练分为两步。先冻结状态编码器训练10轮风险探针，再解冻全网络，用较小的编码器学习率进行微调。每个外折只在其训练车辆内部划分小验证集选择轮数，不能根据外折验证车早停。最终18轮取自五个外折所选轮数的中位数。

训练自动使用CUDA；没有可用GPU时可以回退到CPU。正式运行使用CUDA完成。

## 7. 模型选择与对照实验

V12没有直接采用最复杂模型，而是按以下顺序回答三个问题：

1. 人工整理的六种状态是否优于随机事件分组；
2. 预测未来状态变化是否优于只恢复当前状态；
3. 人工风险链是否优于普通动态网络、无先验图和随机链。

所有对照使用相同的数据划分和训练步数。各方法保持相同的登记参数总数和网络接口，HRC、无先验图与随机链也具有相同的有效图结构容量；State-MAE会关闭未来动态路径，因此它与动态方法的实际有梯度参数量并不相同。这个对照用于回答“启用新增模块是否改善最终预测”，不能把差异严格归因于拓扑本身。预先规定：新增模块的AUC提升小于约0.01且车辆级配对bootstrap区间跨0时，保留更简单模型。

20→40开发集OOF结果如下：

| 方法 | ROC-AUC | PR-AUC | Brier | 相对State-MAE的AUC变化 |
|---|---:|---:|---:|---:|
| **State-MAE** | **0.775154** | 0.574721 | **0.170662** | 0 |
| 随机状态分组 | 0.764163 | 0.549993 | 0.175753 | -0.010991 |
| Dynamics-SSL | 0.776081 | 0.576874 | 0.171328 | +0.000927 |
| 无人工先验图 | 0.771128 | **0.596916** | 0.170438 | -0.004026 |
| 人工风险链HRC | 0.770873 | 0.587088 | 0.171680 | -0.004282 |
| 随机风险链 | 0.768157 | 0.583714 | 0.171559 | -0.006997 |

Dynamics-SSL只提高0.000927 AUC，配对bootstrap区间为`[-0.015106, 0.018844]`，没有可靠增益。人工风险链低于普通动态模型和无先验图，也没有稳定超过随机链。因此最终保留State-MAE。

无人工先验图的PR-AUC最高，但赛题主指标是ROC-AUC，其AUC低于State-MAE，且Brier差异很小，因此没有依据单个辅助指标改换模型。

## 8. 382辆开发车的OOF性能

最终模型在382辆开发车的20→40车辆级OOF结果为：

| 指标 | 数值 |
|---|---:|
| ROC-AUC | **0.775154** |
| AUC 95% bootstrap区间 | `[0.720111, 0.820197]` |
| PR-AUC | **0.574721** |
| Brier | **0.170662** |
| 固定阈值0.5准确率 | **0.717277** |
| 召回率 | 0.428571 |
| 特异度 | 0.847909 |

20→40正例率为`119/382=31.15%`，因此PR-AUC应与31.15%的随机排序基线一起理解。0.5是赛题交付所需的预先固定概率阈值，没有在OOF上调优。

其他可观察预测窗口的AUC为：14→40为0.776490，30→30为0.780274，40→20为0.783565，50→10为0.760534，53→7为0.738741。较短结果窗口的正例更少，指标波动也更大。

V12相对V11三种子Masked集成提高0.001086 AUC，区间跨0；相对V3降低0.012301，区间同样跨0。V12的主要收益是获得了更清楚的状态结构和更好的可审计性，目前没有证据证明它在总体排序上稳定超过V3。因此V12是当前结构化深度学习候选，不能仅凭单次OOF结果宣称它是所有历史版本中最优模型。

## 9. 关键发现

1. **合理的事件分组有方向性价值。** State-MAE比随机状态分组高约0.011 AUC，五折中四折不低于随机分组，但置信区间仍跨0，应视为积极信号而非最终证明。
2. **自监督恢复当前驾驶状态比强行预测未来更稳。** 未来动态模型平均值略高，但折间正负变化明显，增加了复杂度和不稳定性。
3. **人的风险链适合作为待检验假设，不适合作为固定事实。** `U→C→P`在直觉上合理，但当前样本没有证明这套有向图能改善事故排序。
4. **暴露量和数据质量必须显式建模。** 事件少可能来自驾驶少、设备离线或摄像头异常，不能直接解释为安全。
5. **小数据更需要控制模型容量。** 统一对照网络约12万总参数，最终风险概率的有效路径约4.8万参数，已经能表达事件类型、时间变化和状态汇总；继续增加深度或宽度必须通过车辆级OOF证明收益。
6. **准确率不是本题的主要选模指标。** 正负样本不平衡时，固定阈值准确率容易被负例比例影响，模型选择优先依据ROC-AUC，并辅以PR-AUC和Brier。
7. **最终60→40仍是外推。** 按车交叉验证能检验跨车辆泛化，不能创造第61—100天的真实标签。
8. **概率校准证据有限。** Brier用于辅助检查，但尚无第61—100天外部结果或独立校准集；当前概率更适合用于车辆风险排序和候选筛查。

## 10. 输出与异常车辆处理

最终模型使用382辆开发车重新进行1500步自监督预训练和18轮监督微调，再读取每辆车完整60天历史。输出字段为：

```text
gpsno, prediction, probability
```

其中`probability`为未来40天概率，`prediction = 1(probability ≥ 0.5)`。

478辆具有匹配事件源的车辆走完整模型。其余22辆既没有匹配事件源，也没有可观察轨迹或IMU行为，模型不能把这种沉默解释为安全，因此使用开发池20→40的正例先验概率`119/382≈0.3115`，并在内部候选文件中标记为`prior_no_observed_behavior`。最终交付仍覆盖全部500辆车。

## 11. 防泄漏与质量检查

项目已设置以下自动检查：

- 车辆级训练和验证名单无交集；
- 每辆验证车只在一个外折出现；
- 标准化器只拟合训练车辆；
- 修改锚点之后的数据不能改变该锚点预测；
- 遮蔽一个状态时必须同时遮住其完整事件组；
- EMA教师不接收梯度；
- SSL未来事件目标明确排除`11803/11804`；
- 风险链与随机链保持相同参数量；
- 输出500辆车、车辆编号唯一、概率无缺失且位于0—1；
- 二分类结果必须与0.5阈值严格一致。

当前项目全量37项自动测试均已通过。

单模型AUC区间使用1000次车辆级有放回bootstrap，并取2.5%和97.5%分位数；模型差异使用2000次相同车辆索引的配对bootstrap。两种方法的抽样单位都是车辆，随机种子由2026和对应锚点或比较名称确定。
