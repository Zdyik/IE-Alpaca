# 任务一项目架构与实验迭代

这个文件只约定**数据怎样进来、车辆怎样划分、实验怎样比较和保存**。V3 的历史窗口、右删失损失与模型取舍见[任务一事故预测模型设计](../任务一事故预测模型设计.md)。V1 CatBoost、V2 多预测期 GRU 和 V3 Model 0 逻辑风险率已运行；实测结果见[实验记录](实验记录.md)。

## 一条主流程

```text
已有预处理日表 → 冻结车辆名单 → 训练车拟合预处理和模型
                                     ↓
                          车辆级5折验证、少量超参数选择
                                     ↓
                         方案冻结后评估96台独立测试车
                                     ↓
                         重训、输出500车概率与二分类
```

每次实验只创建一个新 `run_id`，不覆盖旧版。该版本文件夹内同时保存运行时源码快照、配置、模型权重、逐车预测、指标和数据指纹。项目目录维护正在开发的代码和设计文档；大数据与实验产物留在本机数据库目录。

## 数据、划分与评价口径

- 数据库根目录：`E:\Databases\2026 清华IE亮剑-算法赛道赛题`。现成输入为 `任务一预处理结果/daily_features.parquet`、`bag_index.parquet`、`profile.parquet`；训练不重跑数十 GB 原始数据。
- 画像表有 500 台目标车辆，478 台在有效期内有可匹配事件记录，是**候选监督车**；这不保证逐日事件通道完整。其余 22 台在事件表中无可匹配记录，不能据此判定传感器缺失，也不能直接当负例。最终对 500 台全部输出。
- 冻结划分文件为 `任务一实验结果/splits/split_v1_seed2026.json`：382 台开发、96 台独立测试。开发组 5 折，每车的所有日期和锚点只进同一个验证折。预处理参数和模型只在该折训练车上拟合。
- 方案选择只看开发组 OOF。V3 先预注册带正则逻辑回归与浅层 CatBoost 各 1–2 个配置，用相同历史统计、landmark、删失损失和车辆折比较。测试组标签只在方案冻结后开启一次；如果后来继续改方案，旧测试分数不能再当作独立确认。
- 比赛最终输出是 **60 天历史→未来 40 天概率**。给定数据不含 07-30 后的结局，因此本地无法测这一组合。06-20 是拥有完整 40 天随访的**最晚锚点**，输入前 20 天，用于本地 40 天回测；更早锚点也有完整 40 天随访。较晚锚点只能验证较短预测期。开发 OOF 和独立测试分数必须注明锚点及预测期。

ROC-AUC 是主排序指标；同时保存正负例数、Accuracy@事先固定阈值、PR-AUC、Brier、混淆矩阵和车辆级 bootstrap 区间。准确率不能单独用来决定方案；同一 60 天内构造的多个锚点不能当作独立车辆来计算置信区间。重复在开发 OOF 上试很多方案会造成选择偏差，所以限制比较次数，保留 96 台测试车作一次最终确认。V3 **不以锚点前是否有事件记录筛车**；与 V1/V2 比较时按车辆配对，若资格以后变化，再于共同车辆重算旧版分数。

## 文件各做什么

```text
IE-Alpaca/
├─ README.md                          如何运行、已有结果
├─ 任务一事故预测模型设计.md            简化的目标、损失、网络、选择规则
├─ preprocess.py                      已完成的原始数据预处理
├─ train_v1.py                        已运行的 CatBoost 基线
├─ train_v2.py                        已运行的多预测期 GRU
├─ configs/experiments/               每版固定配置
├─ src/ie_alpaca/                     日序列、模型、训练、指标与版本保存代码
├─ tests/                             车辆互斥、时间截断、标签和输出契约
└─ docs/实验记录.md                    每版实际分数与取舍

E:\Databases\2026 清华IE亮剑-算法赛道赛题\
├─ 任务一预处理结果\                   500×60的日表及质量报告
└─ 任务一实验结果\
   ├─ splits\split_v1_seed2026.json   所有版本共用的冻结车名单
   ├─ runs\<run_id>\
   │  ├─ source\                      当版源码和配置快照
   │  ├─ models\                      折模型、最终模型、折内缩放器
   │  ├─ predictions\                 OOF、独立测试（若已开启）、500车候选
   │  ├─ metrics.json                  指标和评价口径
   │  ├─ leakage_audit.json            车辆、时间边界检查
   │  └─ manifest.json                 数据指纹、依赖、状态、设备、种子
   └─ leaderboard.csv                  已完成版本的可重建索引
```

旧 V1/V2 代码与结果保留原样。V3 Model 0 使用 `train_v3_model0.py`、`configs/experiments/v3_model0_logistic.json` 和 `src/ie_alpaca/features/landmark_v3.py`；每次运行新建 `V3M0_...` 版本文件夹，保存代码快照、模型、OOF、500 车候选预测和数据指纹。每次主要只改一个因素，并在[实验记录](实验记录.md)写结果与是否继续。

## V3 进度与下一步

1. 已从日表按车构造 `14/20/30/40/50/53` 天锚点的长期、近期、暴露与质量统计，以及后续首次 `11803/11804` 日期和观察截止日；已核对 V1 的 20→40 标签，并用 500 台车的第 20 天输入检查未来记录截断不变性。事件通道独立覆盖信息仍待查。
2. 每锚点压缩为至多两条正/负加权记录，与恒定日风险的逐日 Logloss 等价。Model 0 带正则逻辑回归已经实现；Model 1 浅层 CatBoost 待比较。事件表无匹配记录、但有行为数据时可使用去掉事件衍生特征的回退模型；本批 22 台车行为数据也为空，首版给开发车先验并标记低证据。
3. 已在原 5 折开发车上生成逐车 OOF：14/20→40 检查完整 40 天，30→30、40→20、50→10、53→7 分别诊断长历史；与 V1 的 20→40 结果按 382 台共同车辆配对。仍需审计 7 月中旬目标事件增多是否影响 Day60 外推。
4. 已用 382 台开发车重训并生成 500 台车的 60→40 **候选**概率，供检查输出契约和分布。96 台独立测试车尚未评分；锁定完整方案后只评估一次。最终是否再用 478 台候选监督车重训，由后续选择结果决定。

新模型若没有稳定改善或概率质量变差，就保留较简单的 V1；这个取舍以逐车预测和区间为依据。数据期外的真实 60→40 效果只能由赛方未来标签或官方评测判断。
