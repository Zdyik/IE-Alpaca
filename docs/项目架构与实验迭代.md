# 任务一项目架构与实验迭代规范

**状态：** V1 CatBoost 已在正式处理数据上完成首次开发集 OOF 训练，结果见[实验记录](实验记录.md)；60 天多预测期网络和融合待开发。  
**适用范围：** 任务一事故/未遂事故风险预测；与[模型设计](../任务一事故预测模型设计.md)配套。  
**数据根目录：** `E:\Databases\2026 清华IE亮剑-算法赛道赛题`。

## 1. 设计目标与边界

一次实验应能回答四件事：用了哪版数据和标签、改了什么、在固定验证集上表现怎样、下一次为何这样改。**一次实验就是一个模型版本**，生成独立 `run_id` 和不可覆盖的版本文件夹；该文件夹同时保存当时实际运行的模型代码、配置、预测数据、指标和权重。项目仓库保留持续开发的代码及人的决策，数据库目录保存每版的完整快照和大文件。预处理和训练都只读取比赛允许的原始数据，正式预测仍对画像中的 500 台车逐车输出。

比赛按**车辆级 ROC-AUC**排名，因此它是主排序指标。准确率也要展示，但必须连同阈值及阈值来源一起保存；在小样本和类别不均衡下，单看准确率会掩盖排序与概率质量问题。这里的本地可验证主任务是 **06-20 锚点的 20 天历史 → 后续 40 天结局**。使用完整 60 天历史预测未来 40 天是最终推理目标，现有数据没有其直接监督标签，不得把代理回测 AUC 写成正式任务的实测 AUC。

`任务一预处理结果/versions` 是未来的数据版本化目标，当前 `preprocess.py` 已在处理结果根目录生成完整四源日特征，`make_model_inputs.py` 已在其 `model_inputs` 下生成 20 天张量，并通过 `validation_report.json` 检查。V1 训练直接读取处理结果根目录的三个 Parquet 表，首次真实数据版本为 `V1_20260921_112800_71fbec41`；旧 `output` 归档为“未完成”，不得自动进入训练。

`data_version` 由输入文件清单、时间边界、清洗规则、特征 schema 和标签口径共同确定。任何改变这些因素的实验必须生成新数据版本；单纯修改模型超参数可复用同一数据版本。数据清单至少记录文件路径、大小、修改时间与可选 SHA-256；快速迭代可以先按大小和修改时间发现变更，最终候选应校验哈希。每个版本完成后只读，失败版本标记为失败，不在原目录内修补并覆盖。

## 4. 一次实验的身份与配置

实验配置将引用 `data_version`、`feature_set`、`label_policy`、`split_version`、`model_name`、`seed`、训练预算、预测期、指标与父实验 `parent_run_id`；另外写一句可证伪的假设和本次**唯一主要改动**。运行时固化合并后的配置，`run_id` 可取 `E0007_20260921_1530_<git短哈希>_<配置短哈希>`。即使重新运行同一配置，也创建新 ID，并以 `repeat_of` 指向原运行，避免覆盖。

训练启动前把**实际执行的代码文件内容**复制到该版本的 `source/`，至少包括模型与特征/标签/训练/评估/推理模块、入口脚本、所引用的配置和依赖清单；随后从快照启动，或校验训练所用文件与快照哈希一致。不要只保存 Git commit：未提交的改动也必须原样保存。`source/` 不包含原始数据、中间表、缓存或密钥。`manifest.json` 记录每个快照文件的 SHA-256、Git commit 与工作区状态、配置和数据指纹、依赖版本、设备 CPU/GPU、随机种子、开始结束时间、状态、父实验、异常原因。若训练期间修改代码，改动属于**新版本**，不可回写旧版 `source/`。这样单独打开 `runs/<run_id>` 就能找到代码、预测结果和分数，不依赖当前工作区是否已经迭代。

运行状态为 `planned/running/completed/failed/promoted`；只有校验齐全的 `completed` 才进入排行榜。`predictions/` 的每条记录至少带 `gpsno`、锚点、预测期、折号/数据分组、预测概率和标签状态；提交 CSV 另附同目录的格式校验结果。`leaderboard.csv` 与 `champion.json` 只索引 `run_id` 和版本文件夹中的结果，不另存一份可能脱离代码的预测文件。

单次运行目录先写临时状态，全部产物与校验通过后再原子化标记 `completed`。指标与预测文件是事实来源，`leaderboard.csv` 只是可重建索引。禁止手改排行榜分数或覆盖旧运行；修正统计口径时生成新 `evaluation_version` 和对应报告，并保留原报告。同配置重复训练也建新版本文件夹，用 `repeat_of` 关联，便于查看随机性。

## 5. 固定验证与指标契约

1. **冻结车辆划分。** 先确定可监督车辆与标签质量，再按 `gpsno` 分层生成 `split_version`。同车所有日期、预测期、样本包只进同一折。拆分名单、种子和标签口径一起保存；不得每次试验重新随机划分来挑高分。
2. **开发分数。** 在相同拆分上运行车辆级交叉验证，保存每辆车的外折预测，即 OOF。06-20 的 20→40 ROC-AUC 为主开发指标；同一验证车辆只计一次。V1 用事先固定的超参和 0.5 阈值，不在外折调参；未来的超参、早停、阈值、校准与融合权重只在内层训练车辆上选择。前处理参数也只在训练车辆拟合。
3. **锁定检查。** 多次按开发 OOF 迭代会逐渐适应这批车辆，因此在首次训练前按标签分层留出约 20% 车辆作为锁定组，其余约 80% 做 5 折开发 OOF。V1 已冻结并保存这一划分，使用固定超参、不做折内搜索，也**不计算锁定组指标**。未来对少数预先选定的最终候选做一次锁定检查，再报告置信区间和正负例数量。开发组评价与锁定组评价分开展示；`make_model_inputs.py` 的旧 5 折文件不用于 V1。
4. **准确率的定义。** V1 固定阈值为 0.5，因此 `accuracy@0.5` 和 `accuracy@selected_threshold` 相同；`metrics.json` 明确记为 `fixed_0.5_v1`。未来若调阈值，只能用内层训练预测按预先指定规则选择，并记录规则与阈值。混淆矩阵、召回率、特异度、F1 同步保存；不能在外折预测上挑阈值再报告该折准确率。
5. **其他指标。** 每次保存 ROC-AUC、PR-AUC、Brier、正例率、样本数、折间分布及车辆级 bootstrap 置信区间。PR-AUC 与正例率并列显示。长历史短预测期的 53→7、46→14、39→21、30→30 各自单列；不能平均成“60→40 准确率”。数据覆盖不足的分层统计标注样本数和适用范围。

同一 `data_version + label_policy + split_version + evaluation_version` 的结果才能直接计算配对增益。对同一批车辆的 OOF 概率计算 `ΔROC-AUC` 等及配对 bootstrap 区间；如果数据口径不同，排行榜分组展示，不直接声称模型提升。缺少两类样本的折不能计算 AUC，需显式记为未定义并追查拆分。

## 6. 迭代顺序与决策规则

| 阶段 | 实验 | 主要验证问题 |
|---|---|---|
| 0 | 数据/标签审计与历史 near-miss + 暴露量基线 | 标签可用吗；最简单的排序水平是多少 |
| 1 | CatBoost、LightGBM 同折比较 | 表格特征的稳健上限与关键特征是什么 |
| 2 | 轻量共享时序编码器与多预测期监督 | 时间变化是否提供独立信息；长历史短期任务是否稳定 |
| 3 | 每次增加一组：IMU 极端事件、内部路线、模态遮蔽、删失损失、排序损失 | 该组是否带来一致的配对增益与可接受的校准 |
| 4 | 等权与内层定权融合 | 分支错误是否互补，融合是否真正优于最强单模型 |
| 5 | 最终候选锁定检查、全合格车重训、500 车提交校验 | 结果稳定、范围完整、概率合法且可重现吗 |

每次运行前在[实验记录](实验记录.md)写假设与改动，运行后填指标、误差分析、接受/回退结论和下一步。优先保留同数据同拆分的可配对实验。若 AUC 提升小于抽样波动，或 Brier/缺测压力测试明显恶化，先视为未证实，重复种子或简化特征；不因单次最高分直接晋升 `champion`。`champion.json` 记录模型版本、选择依据、适用的代理指标、锁定检查结果与限制。正式提交文件要额外验证 500 个唯一 `gpsno`、概率在 `[0,1]`、无缺失、列名及顺序符合赛题。

## 7. 落地顺序

V1 已完成首次真实数据训练，保存了冻结拆分、near-miss/暴露量特征、CatBoost 与暴露量回退模型、开发集 OOF、指标和完整代码快照。下一步先复核暂定负例与缺事件源车辆的标签质量，再比较 LightGBM、共享时序编码器、多预测期标签和折内融合。当前结果只能称为 20→40 代理任务表现，不能宣称完整 60→40 新架构已经验证。
