# 任务二司机安全评价模型说明

## 一、评分对象与目标

数据以车辆编号`gpsno`为主体，没有单独的司机编号，因此本模型首先输出车辆安全分。车队能够确认一车一人时，可直接作为对应司机的安全评价；多人共车或司机换车时，需要先按行程建立人车对应关系，再汇总到司机。

模型根据每辆车60天的驾驶记录给出0–100分安全分：

- 分数越高，风险越低；
- 每项扣分对应明确的驾驶行为或风险状态；
- 数据不足的车辆单独标记，不能把“没有记录”解释为安全；
- 分数用于确定提醒、培训和复核顺序。

## 二、评分维度与权重

安全分由六项扣分组成，总扣分上限为100分。

| 评分维度 | 最高扣分 | 主要依据 | 设置理由 |
|---|---:|---|---|
| 事故与未遂事故 | 30分 | 事故、未遂事故 | 已经发生的严重结果 |
| 碰撞与周边冲突 | 20分 | 前碰撞预警、车距过近、盲区报警 | 已接近碰撞状态 |
| 疲劳与注意力 | 15分 | 闭眼、困倦、分心、看手机、打电话、低头等 | 司机注意状态异常 |
| 超速行为 | 15分 | 路口、弯道、危险路段、匝道、长下坡超速 | 不同道路场景的速度风险 |
| 车辆控制稳定性 | 15分 | 车道偏移、长时间压线、IMU剧烈变化 | 车辆操控开始失稳 |
| 风险持续与恶化 | 5分 | 近期增加、连续发生、反复出现 | 风险正在累积或恶化 |

权重按结果严重程度和风险链位置分配。事故与未遂事故权重最高；碰撞和周边冲突属于近端信号；疲劳、超速和控制稳定性分别对应不同管理措施；趋势项只作为近期恶化的附加扣分。数据质量影响评分可信度，不直接扣司机或车辆分数。

## 三、计算方法

### 1. 单个事件风险

对每种事件，先统计五个基础量，再组成四项风险指标：

- `N`：60天内发生次数；
- `km`：60天有效行驶里程；
- `hour`：60天有效驾驶小时；
- `day`：出现该事件的天数；
- `d`：距离最近一次事件的天数。

参考车辆为任务一五折开发集中的382辆车。`P(x)`表示`x`在参考车辆中的百分位，取值为0–1；数值相同时取并列位置的中点。事件指标只与参考车辆中的正值比较，没有发生过该事件时风险为0。

**事件风险 = `0.35 × P(log(1 + 1000N/(km+100))) + 0.25 × P(log(1 + 100N/(hour+1))) + 0.20 × P(day/60) + 0.20 × exp(-d/14)`**

四项分别表示单位里程发生率、单位时间发生率、发生是否持续以及最近是否仍在发生。里程和时长分母中的平滑项用于降低低暴露车辆的偶然波动。

### 2. 同一维度内的事件权重

V12用于判断某种事件对风险预测的影响：将该事件从输入中遮去，观察车辆风险概率的平均绝对变化，记为`Iₑ`。某维度包含`n`种事件时，事件权重为 **`wₑ = 0.5 × (1/n) + 0.5 × Iₑ/ΣI`**。

一半保留均匀权重，防止小样本下单个事件权重过度放大；另一半由V12学习。若某一维度内所有`Iₑ`均为0，则学习部分也使用均匀权重。所有权重非负，同一维度内相加为1。

普通维度风险按 **`维度风险 = Σ(wₑ × 事件风险ₑ)`** 计算。

车辆控制稳定性同时使用事件和IMU，计算式为 **`控制风险 = 0.75 × 控制类事件风险 + 0.25 × IMU异常百分位`**。

IMU异常值由加速度峰值、加速度波动和角速度峰值三项组成，三项按有效观测等权合并：**`IMU原始异常值 = Σ log(1 + |xₜₘ|) / 有效观测总数`**。

其中`t`表示日期，`m`表示三项IMU指标。再把每辆车的IMU原始异常值按参考车辆的全部取值转换为百分位，得到`IMU异常百分位`。

风险持续与恶化只统计前五个维度内的风险事件。先把每天是否出现任一风险事件记为0或1，再计算：最近14天出现比例`R`、前46天出现比例`B`、增加幅度`max(R-B,0)`以及60天内最长连续出现天数。

**趋势风险 = `0.50 × P(R) + 0.30 × P(max(R-B,0)) + 0.20 × P(最长连续天数)`**

三项没有风险事件时均记为0，正值按参考车辆百分位计算。

### 3. 分项扣分与安全分

**分项扣分 = 该维度最高扣分 × 该维度风险**  
**安全分 = 100 - 六项扣分之和**

安全分限制在0–100之间。六项扣分必须能够逐项还原总分。

### 4. 数据可信度

评分可信度由事件源、轨迹和IMU覆盖情况计算：**`可信度 = 0.50 × 事件源是否可用 + 0.30 × 轨迹覆盖率 + 0.20 × IMU覆盖率`**。

可信度不低于0.80记为高，0.50–0.80记为中，低于0.50记为低。低可信度车辆使用参考车辆在各维度风险的中位数估计分数，并标记为U级，补齐数据前不参与排名、奖励或处罚。

## 四、V12状态与评分维度的关系

V12把驾驶记录表示为六类状态。任务二沿用这套风险逻辑，但会按照管理措施重新组织具体事件，并非逐项照搬模型中的主状态标签：

| V12状态 | 在评分模型中的作用 |
|---|---|
| 暴露机会 O | 作为里程和时长分母，不直接扣分 |
| 上游危险行为 U | 拆分为疲劳与注意力、超速行为两个维度 |
| 控制稳定性 C | 对应车辆控制稳定性扣分 |
| 近端险情 P | 对应碰撞与周边冲突扣分 |
| 严重历史 H | 对应事故与未遂事故扣分 |
| 证据质量 Q | 形成可信度等级，不直接扣分 |
| 时间变化 | 形成风险持续与恶化扣分 |

真正构成驾驶风险阶段的是`U → C → P → H`，也就是：**疲劳、分心、超速 → 车辆控制不稳定 → 碰撞预警、车距过近、盲区冲突 → 未遂事故或事故**。

例如，V12把盲区报警放在暴露机会状态，用来描述车辆遇到周边冲突的机会；任务二则把它列入“碰撞与周边冲突”，便于直接对应盲区观察训练。类似调整只改变管理归类，不改变原始事件数据。

评分模型使用V12的事件遮蔽敏感度确定事件重要程度，但不直接读取V12的32维状态向量。各项扣分由事件统计、IMU指标和时间趋势按前述公式计算，再汇总为0–100分。暴露状态负责校正“开得多”，证据质量负责识别“看不见”，两者不直接改变安全表现评价。

## 五、评分结果

每辆车输出：

- 安全总分和风险等级；
- 六个维度的风险值与扣分；
- 主要扣分维度；
- 贡献最大的三个具体事件；
- 数据可信度；
- 管理建议。

示例如下：

| 项目 | 示例内容 |
|---|---|
| 车辆安全分 | 68分 |
| 等级 | D，高风险 |
| 主要问题 | 疲劳与注意力扣9分，车辆控制扣8分 |
| 主要事件 | 疲劳闭眼、频繁低头、右车道偏移 |
| 建议 | 24小时内人工复核，安排疲劳驾驶和车道保持专项培训 |

本次500辆车的等级分布为：A档4辆、B档69辆、C档216辆、D档135辆、E档54辆、U档22辆。

## 六、安全等级

| 等级 | 安全分 | 管理含义 |
|---|---:|---|
| A | 90–100 | 安全表现稳定 |
| B | 80–89 | 风险较低 |
| C | 70–79 | 中等风险，需要针对性提醒 |
| D | 60–69 | 高风险，需要重点管理 |
| E | 0–59 | 极高风险，需要立即复核 |
| U | 数据可信度低 | 先检查设备和数据链路 |

## 七、车队管理方法

### 日常提醒

- 当天发生事故或未遂事故：立即告警；
- 7天内下降10分以上：立即复核；
- 同一种高危行为连续3天出现：专项提醒；
- 某个维度持续恶化：通知车辆负责人和安全管理员。

### 分级管理

| 等级 | 管理措施 |
|---|---|
| A | 正常月度复盘，可进入安全奖励候选 |
| B | 每周反馈主要扣分项 |
| C | 安排针对性培训，14天后重新评价 |
| D | 24小时内人工复核，专项培训并加强监控 |
| E | 立即人工核查，必要时暂停高风险线路或任务 |
| U | 检查摄像头、轨迹和IMU数据，补齐证据前暂缓奖惩 |

### 针对问题安排措施

| 主要扣分原因 | 对应措施 |
|---|---|
| 事故与未遂事故 | 事故复盘、线路和班次检查、责任人面谈 |
| 碰撞与周边冲突 | 跟车距离、防御性驾驶和盲区观察训练 |
| 疲劳与注意力 | 排班检查、休息管理、手机和分心专项培训 |
| 超速行为 | 分道路场景复盘、限速规则培训 |
| 车辆控制稳定性 | 车道保持和平稳操作训练，同时排查车辆状态 |
| 风险持续恶化 | 提高复评频率，检查近期路线、班次和工作负荷变化 |

评分用于发现风险和确定管理顺序。D、E级、单次事故或未遂事故、数据可信度不足、分数短期大幅下降及设备异常等情况均需人工复核。
